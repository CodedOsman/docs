## Overview

The Pico uses a push button to simulate whether a door is open and raises an alert only if the button stays pressed for too long.

Doors that remain open can create security, privacy, or sanitation problems, so the alert should depend on duration rather than a brief opening.

This Pico 2 W prototype uses a push button, LED, and buzzer for timed door-open alerts.

Button-based door-state simulation, timing-based alerts, and simple occupancy-security logic.

## Step-by-Step Assembly

1. Wire the push button between GPIO 14 and 3.3V so the pin reads high when the button is pressed. Holding the button simulates an open door.
2. Connect the LED to GPIO 15 through a 220 ohm resistor and connect the LED cathode to GND.
3. Connect the buzzer positive pin to GPIO 16 and the negative pin to GND.
4. Hold and release the button while watching the raw button state before enabling the timed alert.

## Full Project Code

After completing and checking the circuit connections, open Thonny IDE, copy and paste this code into a new file or upload the project file to the Raspberry Pi Pico 2 W, then run it from Thonny.

```python
from machine import Pin
import time

BUTTON_PIN = 14
LED_PIN = 15
BUZZER_PIN = 16
OPEN_ALERT_MS = 10000

button = Pin(BUTTON_PIN, Pin.IN, Pin.PULL_DOWN)
led = Pin(LED_PIN, Pin.OUT)
buzzer = Pin(BUZZER_PIN, Pin.OUT)
open_since_ms = None

print('Door open alert ready')
print('Hold the button to simulate an open door')

while True:
    door_open = button.value() == 1
    now = time.ticks_ms()

    if door_open:
        if open_since_ms is None:
            open_since_ms = now
        open_duration = time.ticks_diff(now, open_since_ms)

        if open_duration >= OPEN_ALERT_MS:
            status = 'ALERT'
            led.on()
            buzzer.on()
        else:
            status = 'OPEN TIMING'
            led.off()
            buzzer.off()
    else:
        open_since_ms = None
        status = 'CLOSED'
        led.off()
        buzzer.off()

    print('Status:', status)
    time.sleep_ms(500)
```

### Validation Checks

- **Normal condition test**: confirm the system stays in its safe or idle state under baseline conditions
- **Warning condition test**: hold the button for just under the chosen threshold and confirm no alert occurs
- **Critical condition test**: hold the button longer than the threshold and confirm the LED and buzzer activate
- **Timing test**: compare the alert delay with a stopwatch or repeated trial
- **Limitation test**: note that the push button simulates a door state; it does not detect a physical door

### Deployment and Limitations

- This prototype can be used for local warning demonstrations and early field trials
- Before deployment, it needs enclosure protection, calibration records, and a clear response procedure
- Alert systems should always be treated as decision-support tools unless they are certified for the application

## Troubleshooting

| Problem | Possible Cause | Solution |
|---------|----------------|----------|
| Button press is not detected | Button wiring is incorrect | Check that the button drives GPIO 14 high when pressed |
| Alert never starts | The threshold is too long or the button is not held long enough | Lower `OPEN_ALERT_MS` for a quick validation test |
| Alert starts immediately | GPIO 14 is held high by incorrect wiring | Check that the button connects only between GPIO 14 and 3.3V |
| Buzzer never sounds | Buzzer wiring is wrong or the alert duration is never reached | Test the buzzer directly and then hold the button beyond the threshold |
